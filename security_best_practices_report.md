# Security Best-Practices Review

Review date: 2026-07-15
Scope: the browser application, PWA service worker, build scripts, persisted client state, public-data integrations, and test/dependency configuration.

## Executive summary

No critical vulnerabilities remain in the reviewed code. This refactor resolved the highest-impact issues found: executable-script policy was missing, proxy configuration accepted unsafe transport and credential-bearing URLs, outbound requests did not consistently suppress ambient credentials/referrers, and persisted/remote data crossed trust boundaries without consistent validation.

The remaining material risk is architectural: public CORS proxies can observe and alter the public market-data requests they relay. Response validation now limits the effect of malformed data, but it cannot provide authenticity. A trusted first-party relay is the recommended long-term mitigation.

Dependency audit result: `npm audit --audit-level=moderate` reported 0 vulnerabilities.

## Critical severity

No findings.

## High severity — resolved

### SEC-01 — Executable content lacked a restrictive CSP

Status: resolved.

The application now applies a deny-by-default CSP, blocks inline event handlers, restricts scripts to self plus the pinned chart CDN, disables objects/forms/base rewriting, and limits network and asset sources (`index.html:5`). Inline script hashes are regenerated by `scripts/sync-csp.mjs:10-55` through the build/test workflow in `package.json:6-14`. Browser coverage confirms an unapproved inline script is blocked (`tests/smoke.spec.js:192`).

### SEC-02 — Proxy settings allowed unsafe transport and credential-bearing URLs

Status: resolved.

Proxy URLs now use structured URL parsing, reject embedded credentials and fragments, require HTTPS, and permit HTTP only on `localhost` or `127.0.0.1` for development (`index.html:3870-3905`). Invalid persisted proxy entries are removed before use (`index.html:3907-3927`). Regression coverage exercises HTTPS, loopback, remote HTTP, credentials, and unsupported IPv6 loopback (`tests/settings.spec.js:163`, `tests/coverage.spec.js:205-212`).

## Medium severity — resolved

### SEC-03 — Remote and persisted data was insufficiently validated

Status: resolved.

Trust-boundary validation now covers:

- saved custom profiles and bounded filters (`index.html:4473-4515`, `index.html:6755-6811`);
- chart settings and color-only style overrides (`index.html:4590-4613`, `index.html:5373-5410`);
- finite, ordered OHLCV candle data (`index.html:4823-4849`);
- response-size limits, market-symbol shape, finite/ranged market metrics, record caps, and strict legacy keys (`index.html:4851-4905`, `index.html:5473-5559`, `index.html:5599-5607`).

Malformed storage, candles, symbols, and infinite values are covered in `tests/settings.spec.js:214-250` and `tests/coverage.spec.js:185-294`.

### SEC-04 — Cross-origin requests could carry ambient credentials or referrer data

Status: resolved.

All application fetch helpers now enforce `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`, even if a caller attempts to override them (`index.html:4019-4024`). Dynamic third-party script loading also suppresses referrer data (`index.html:4034-4044`). Regression coverage is in `tests/settings.spec.js:181-212`.

### SEC-05 — Scan retries could exceed the intended user-visible timeout

Status: resolved.

The scan now propagates one absolute 15-second deadline through direct and proxy attempts, bounds every request by the remaining time, and returns an actionable timeout (`index.html:5641-5713`, `index.html:6641-6662`). This reduces resource exhaustion and prevents an apparently stuck UI. The remaining-deadline path is covered at `tests/settings.spec.js:252-279`.

## Medium severity — remaining

### SEC-06 — Public proxy integrity and privacy are not guaranteed

The default fallback chain includes third-party public proxies (`index.html:3861-3869`). Those services can observe requested market endpoints and symbols, return stale data, or alter responses. Schema and range validation reduce malformed-data impact, and the UI warns users about proxy risk, but the application cannot authenticate proxied content.

Recommendation: operate a trusted first-party HTTPS relay with an allowlist of upstream market-data hosts, response-size limits, rate limiting, and monitoring. Once available, remove public defaults and narrow `connect-src` from general HTTPS to explicit origins.

## Low severity — remaining

### SEC-07 — CSP is delivered through HTML metadata rather than an HTTP header

The meta policy at `index.html:5` protects the document after parsing reaches it, but metadata cannot express every response-header control, including `frame-ancestors`. It also cannot protect a compromised response before the policy is parsed.

Recommendation: if deployment moves to a host with header control, send the same CSP as an HTTP response header and add an appropriate `frame-ancestors` policy. Keep the meta policy as defense in depth for standalone-file use.

### SEC-08 — Chart rendering depends on a third-party CDN

Lightweight Charts is loaded from an exact version on unpkg and protected with SHA-384 SRI, CORS, a no-referrer policy, and a load timeout (`index.html:4013-4014`, `index.html:4034-4067`). Integrity is mitigated, but CDN availability remains external.

Recommendation: self-host the pinned artifact if offline reliability or third-party availability becomes a stronger requirement.

## Informational — accepted trade-off

### SEC-09 — Inline styles require `style-src 'unsafe-inline'`

The single-file distribution model uses an inline stylesheet and runtime style properties, so the policy permits inline styles (`index.html:5`). Script execution remains hash-restricted, and persisted chart colors are allowlisted and normalized before reaching CSS (`index.html:5373-5410`).

Recommendation: move CSS into a versioned local stylesheet if eliminating `unsafe-inline` becomes a priority; this is not required for the current threat model.

## Review limitations

This was a local static/code review with automated browser validation. It did not include penetration testing of third-party proxy operators, a production-header scan, or authenticated testing against external services. The application has no server-side authentication, authorization, database, or secret-management surface in this repository.
